# 2. 详细设计

## 2.1 前端迭代目标

本次迭代实现成员D负责的全部前端页面，功能覆盖 **B端 8 个页面 + C端 1 个页面**，完成以下业务闭环：

**B端（HR工作台）**：
1. **Dashboard** — 统计卡片、招聘漏斗、投递趋势图、待办事项（P0）
2. **人才库（候选人列表）** — 候选人表格、Top5高潜推荐卡片、筛选排序、标记操作
3. **面试协同** — 面试安排列表、面试评估表单、AI反馈生成
4. **Offer管理** — Offer列表、发起Offer表单、HC概览、催促功能
5. **消息通知** — 通知列表、未读标记、类型筛选、全部标为已读、HTTP轮询刷新
6. **消息沟通** — 会话列表、聊天区域（消息气泡）、HTTP轮询刷新
7. **公司管理** — 公司信息编辑、成员管理列表、添加面试官弹窗
8. **个人中心** — 账号信息、修改密码、通知偏好、操作日志、退出登录

**C端（求职者平台）**：
9. **模拟面试** — 岗位选择、答题界面（题号/计时器/作答区/评分卡片）、面试报告

## 2.2 迭代具体描述

### 2.2.1 B端 Dashboard（数据统计工作台）

> **原型参考**：企业端 → 工作台

##### UI&交互

**整体布局**：上下结构。顶部为统计卡片行（4个指标卡片横排），中部为图表区（左侧大图+右侧小图），底部为待办事项列表。

###### 页面加载流程

```
进入B端工作台
  ↓
展示全屏骨架屏（4个统计卡片占位 + 图表区灰色占位 + 待办列表骨架）
  ↓
并行请求：/api/hr/dashboard/stats | /api/hr/dashboard/trend | /api/hr/dashboard/funnel
  ↓
所有数据返回后，骨架屏淡出（300ms），实际内容淡入（300ms）
  ↓
定时轮询统计数字：每60秒静默刷新统计卡片数据（不显示loading），图表不轮询
```

###### 统计卡片区交互

- 4个统计卡片横向排列：今***投递 | 待处理 | 面试安排 | 本月录用
- 每个卡片包含：图标（彩色圆形背景）、数值（大号加粗数字）、标签文字、环比变化（绿色↑/红色↓ + 百分比）
- 卡片hover效果：轻微上浮（translateY: -2px）+ 阴影加深，cursor变为pointer
- 点击"今***投递"卡片 → 跳转人才库页面，默认筛选为"今天"
- 点击"待处理"卡片 → 跳转人才库页面，默认筛选为"待筛选"
- 点击"面试安排"卡片 → 跳转面试协同页面，Tab切换到"面试安排"
- 点击"本月录用"卡片 → 跳转Offer管理页面，筛选"已确认"
- 数字变化时展示动态滚动动画（数字从旧值滚动到新值，持续时间800ms）

###### 投递趋势图交互

- 图表类型：折线图（AntV Line），位置在页面中部左侧，宽度占60%
- X轴：日期（近30天），Y轴：投递数量
- 折线为渐变蓝色，数据点hover时展示tooltip（日期 + 投递数）
- 图表上方有日期范围切换按钮组：最近7天 | 最近30天 | 本月 | 本季度
- 切换日期范围 → 图表数据重新请求，折线重新渲染，有200ms过渡动画
- 右上角"导出"按钮 → 点击后导出当前视图为CSV（含日期+投递数列）

###### 招聘漏斗图交互

- 图表类型：漏斗图（AntV Funnel），位置在投递趋势图右侧，宽度占40%
- 漏斗层级从上到下：曝光量 → 投递量 → 筛选通过 → 进入面试 → 录用
- 每层显示：层级名称、数量、转化率（上一级→本级）
- 层级颜色从深蓝渐变到浅蓝（顶部最深）
- hover某层时：该层放大5%，展示详细tooltip（总数、本层数量、转化率、环比变化）
- 可在顶部"全部岗位"下拉框中切换查看某个具体岗位的漏斗

###### 待办事项列表交互

- 位置：页面底部，标题为"待办事项"，右侧显示待办数量badge
- 每行显示：优先级颜色条（红色=紧急，橙色=普通）+ 事项内容 + 时间 + 操作按钮
- 事项类型包括：
  - "有3份简历超过24小时未查看" → [立即查看] 按钮，跳转人才库
  - "XX的面试评估已超时24小时" → [录入评估] 按钮，跳转面试协同
  - "XX的Offer已发送3天未确认" → [查看Offer] 按钮，跳转Offer管理
  - "岗位"XX岗位"HC仅剩1个" → [查看岗位] 按钮，跳转岗位管理
- 无待办事项时展示空状态："暂无待办事项 🎉"，居中展示，灰色文字
- 支持按类型筛选：全部 | 简历筛选 | 面试评估 | Offer跟进

###### 统计卡片字段

| 字段名称 | 说明 | 图标 | 点击跳转 |
| --- | --- | --- | --- |
| 今***投递 | 今日收到的简历数量 | FileTextOutlined | 人才库（筛选：今天） |
| 待处理 | 待筛选的简历数量 | ClockCircleOutlined | 人才库（筛选：待筛选） |
| 面试安排 | 本周待面试数量 | CalendarOutlined | 面试协同（Tab：面试安排） |
| 本月录用 | 本月已发Offer并确认的数量 | CheckCircleOutlined | Offer管理（筛选：已确认） |

##### 前端逻辑

###### 数据刷新策略

- 首次加载：全屏骨架屏，并行请求所有接口
- 统计数字：每60秒静默轮询刷新，数字滚动动画
- 图表数据：仅在切换日期范围或切换岗位时重新请求
- 待办事项：每120秒静默轮询刷新
- 网络异常时：顶部展示Alert警告"数据加载失败，点击重试"，点击触发重新请求

##### 所需API

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/hr/dashboard/stats` | GET | 统计卡片数据：今***投递、待处理、面试安排、本月录用、环比变化 |
| `/api/hr/dashboard/trend` | GET | 投递趋势折线图数据，参数：`days`（7/30/本月/本季度） |
| `/api/hr/dashboard/funnel` | GET | 招聘漏斗数据，参数：`jobId?`（可选，按岗位筛选） |

### 2.2.2 B端 人才库（候选人列表）

> **原型参考**：企业端 → 人才库

##### UI&交互

**整体布局**：上下结构。顶部为筛选栏 + 排序栏，中间为Top5高潜推荐卡片区（固定展示），底部为候选人表格。

###### 页面加载流程

```
进入人才库页面
  ↓
顶部展示TableSkeleton（表格骨架屏），Top5区域展示CardSkeleton（5张卡片占位）
  ↓
并行请求：/api/hr/candidates/top5 | /api/hr/candidates/list
  ↓
数据返回后，骨架屏淡出，实际内容淡入
  ↓
筛选/排序变更 → 表格进入loading状态（Spin覆盖表格区域，Top5区域不刷新）
```

###### 筛选栏字段

| 字段名称 | 说明 | 输入方式 | 是否必填 | 默认值 | 字段类型 | 提示文案 | 数据源 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 投递状态 | 按候选人当前状态筛选 | Select 多选 | N | 全部 | string[] | 请选择状态 | 全部/已投递/HR已查看/筛选通过/面试中/可录用/已录用/已淘汰/已撤回 |
| 匹配度范围 | 按匹配度区间筛选 | Select 单选 | N | 全部 | string | 请选择匹配度 | 全部/70%+/80%+/85%+/90%+ |
| 投递岗位 | 按投递的岗位筛选 | Select 可搜索单选 | N | 全部岗位 | string | 请选择岗位 | 接口返回企业的岗位列表 |
| 关键词搜索 | 按候选人姓名或技能搜索 | Input.Search | N | 空 | string | 搜索候选人姓名或技能 | — |

**筛选交互细节**：
- 切换任意筛选项 → 列表即时刷新（300ms debounce），Top5推荐区域保持不变
- "重置"按钮在筛选栏右侧，仅在筛选项非默认值时显示，点击后恢复所有筛选项为默认值并触发搜索
- 搜索框输入后按回车或点击搜索图标触发，输入过程中不做实时搜索
- 每个筛选条件选中后在Select内展示Tag，点击Tag的×可单独移除该条件

###### 排序栏

| 排序方式 | 说明 | 默认 |
| --- | --- | --- |
| 匹配度降序 | 与岗位的匹配度从高到低 | ✅ 默认 |
| 投递时间倒序 | 最近投递的在前 | — |
| AI评分降序 | 简历综合评分从高到低 | — |

**排序交互细节**：Radio.Button 组样式切换，点击即时生效，列表重新排序（前端重排当前页数据）。

###### Top5高潜推荐卡片区

**卡片布局**：
- 5张卡片横向排列，超出时可左右滚动（Arrows 按钮在区域两侧）
- 每张卡片宽度固定320px，卡片之间间距16px
- 卡片头部：排名徽章（🏆Top1/Top2/.../Top5）+ 候选人姓名 + 匹配度百分比（大号彩色数字）

**卡片内容结构**：
```
┌──────────────────────────────────────┐
│ 🏆 Top 1  李婷    匹配度 92%        │ ← 头部：排名+姓名+匹配度
│ ─────────────────────────────────── │
│ ✅ 匹配优势：                        │
│  · React项目经验3年实战              │
│  · TypeScript超出岗位基本要求        │
│  · 有跨部门协作项目经验              │
│                                     │
│ ⚠️ 适配风险：                        │
│  · 架构设计经验偏少                  │
│ ─────────────────────────────────── │
│ [查看简历] [标记合适] [发消息] [不感兴趣]│ ← 操作按钮行
└──────────────────────────────────────┘
```

**卡片交互细节**：
- 匹配度 ≥ 85%：匹配度数字显示绿色 + 绿色渐变背景边框
- 匹配度 70-84%：匹配度数字显示蓝色 + 蓝色渐变背景边框
- 匹配度 < 70%：匹配度数字显示橙色 + 橙色渐变背景边框
- hover时：卡片上浮4px + 阴影加深 + 底部操作按钮显示（正常态按钮透明度0.7）
- 点击"不感兴趣"：卡片执行缩小+淡出动画（300ms），从列表移除，调用后端接口标记
- 点击"查看简历"：右侧滑出Drawer（宽度60%屏幕），展示结构化简历+能力雷达图
- 点击"标记合适"：弹出确认气泡"确认标记该候选人为合适？"，确认后按钮变为已操作状态并置灰
- Top5数据来源于匹配引擎计算，每次进入页面或手动刷新时更新

**会话创建规则**：
- HR首次给某候选人发消息时，系统自动创建会话（关联候选人+投递岗位+HR所在企业）
- 求职者在C端点击「咨询HR」后，对应企业的HR可在消息沟通页面看到新会话
- 同一候选人对同一企业的多个投递岗位，共用同一个会话（以企业维度聚合）
- 会话创建后双方均可发起消息，无需对方先发

## 5. 其他

### 5.1 风险评估

| 风险 | 影响 | 概率 | 应对策略 |
| --- | --- | --- | --- |
| SSE流式展示兼容性 | 模拟面试出题/报告SSE流式展示在部分浏览器不兼容 | 低 | 降级为轮询方式获取结果 |
| AntV图表在Umi4中兼容性 | 漏斗图/折线图渲染异常 | 中 | 提前验证AntV与Umi4版本兼容性，准备ECharts为备选 |
| 面试8题作答数据丢失 | 用户刷新页面导致作答丢失 | 高 | 每道题作答后实时保存到LocalStorage，页面恢复时自动回填 |
| 评语字数校验 | 前端校验与后端不一致 | 低 | 统一使用后端返回的校验规则，前端做预校验 |
| HTTP轮询性能 | 消息通知和消息沟通轮询请求频率高 | 低 | 页面失焦时暂停轮询，轮询间隔可配置，返回304时无数据不更新DOM |

### 5.2 稳定性保障

- **容量评估**：B端Dashboard并发请求约10 QPS，消息通知/沟通轮询总计约30 QPS
- **兼容性**：支持Chrome 90+、Edge 90+、Safari 14+
- **回滚计划**：前端采用版本化构建部署，每次发布生成独立目录，Nginx配置支持快速切换
- **容错处理**：所有页面均需覆盖Loading、Empty、Error三种状态
