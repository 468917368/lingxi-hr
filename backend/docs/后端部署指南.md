# 灵犀互聘 后端部署指南

> 部署方式：服务器装 JDK 8 + Docker 跑基础设施（MySQL/Redis/RocketMQ/Nacos），后端 7 个服务打成 **fat jar 直接在服务器上运行**。

## 部署架构

| 机器 | 内网 IP | 内容 |
|------|--------|------|
| 8G 后端机 | 172.17.24.42 | Docker：MySQL/Redis/RocketMQ/Nacos；后端 7 个服务（`java -jar`） |
| 4G 前端机 | 172.31.40.171 | 前端 + nginx（待部署） |

后端 7 个服务端口：

| 服务 | 端口 | JVM 堆 |
|------|:---:|:---:|
| lingxi-gateway | 8080 | 384m |
| lingxi-user | 8086 | 512m |
| lingxi-chat | 8087 | 384m |
| lingxi-job | 8082 | 512m |
| lingxi-resume | 8083 | 768m |
| lingxi-hr | 8084 | 512m |
| lingxi-admin | 8085 | 384m |

服务直接连本机 `127.0.0.1` 的基础设施端口（3306/6379/8848/9876）；注册到 Nacos 的地址是 `172.17.24.42`。

## 一、服务器环境准备（8G 机）

### 1. 安装 JDK 8

```bash
sudo dnf install -y java-1.8.0-openjdk-devel
java -version
```

### 2. Docker 镜像加速

```bash
tee /etc/docker/daemon.json <<'EOF'
{"registry-mirrors":["https://0x96fcce.mirror.aliyuncs.com"],"log-driver":"json-file","log-opts":{"max-size":"100m","max-file":"3"}}
EOF
systemctl daemon-reload && systemctl restart docker
```

### 3. 基础设施（Docker）

```bash
# 网络 + 数据目录
docker network create mynet
mkdir -p /data/mysql /data/redis /data/rocketmq/namesrv/logs /data/rocketmq/broker/{logs,store} /data/nacos

# MySQL（挂 schema.sql 首次自动建 34 张表）
docker run -d --name mysql --network mynet -p 3306:3306 --memory 512m \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -v /data/mysql:/var/lib/mysql \
  -v /data/init/schema.sql:/docker-entrypoint-initdb.d/01-schema.sql:ro \
  --restart=always mysql:8.0 \
  --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci

# Redis（密码 123456，与各服务 REDIS_PASS 一致）
docker run -d --name redis --network mynet -p 6379:6379 --memory 256m \
  -v /data/redis:/data --restart=always \
  redis:7-alpine redis-server --appendonly yes --requirepass 123456

# Nacos 2.2.3（⚠ 容器内存要 768m，512m 会 OOM 反复重启）
docker run -d --name nacos --network mynet -p 8848:8848 -p 9848:9848 \
  --memory 768m -e MODE=standalone \
  -e JVM_XMS=256m -e JVM_XMX=512m -e JVM_XMN=128m \
  -v /data/nacos:/home/nacos/data --restart=always \
  nacos/nacos-server:v2.2.3

# RocketMQ NameServer + Broker
# ⚠ namesrv 必须 768m + 限制 JVM 堆（256m 会 OOM 反复重启，导致依赖 MQ 的服务启动失败）
docker run -d --name rocketmq-namesrv --network mynet -p 9876:9876 --memory 768m \
  -e "JAVA_OPT_EXT=-Xms256m -Xmx512m" \
  -v /data/rocketmq/namesrv/logs:/home/rocketmq/logs --restart=always \
  apache/rocketmq:5.1.0 sh mqnamesrv

docker run -d --name rocketmq-broker --network mynet \
  -p 10909:10909 -p 10911:10911 -p 10912:10912 --memory 512m \
  -e "JAVA_OPT_EXT=-Xms256m -Xmx512m" \
  -v /data/rocketmq/broker/logs:/home/rocketmq/logs \
  -v /data/rocketmq/broker/store:/home/rocketmq/store --restart=always \
  apache/rocketmq:5.1.0 sh mqbroker -n rocketmq-namesrv:9876
```

**基础设施初始化**：

```bash
# ① MySQL 建表（若没挂 init 脚本，手动导入）
docker exec -i mysql mysql -uroot -p123456 < schema.sql
docker exec -it mysql mysql -uroot -p123456 -e "USE lingxi; SHOW TABLES;" | wc -l   # ≈34

# ② Nacos 命名空间 lingxi（必须建，否则服务互不可见、网关 503）
sleep 40 && curl -X POST "http://127.0.0.1:8848/nacos/v1/console/namespaces" \
  -d "customNamespaceId=lingxi&namespaceName=lingxi"
```

## 二、构建 fat jar（本地）

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-8.jdk/Contents/Home
mvn clean package -DskipTests
# 产物：各模块 target/xxx-1.0.0-SNAPSHOT.jar（可执行 fat jar）
```

> 必须 JDK 8 编译（默认 JDK 26 会让 Lombok 注解处理失败）。

## 三、上传到服务器

```bash
ssh root@121.40.45.122 "mkdir -p /opt/lingxi/app"
scp -r services root@121.40.45.122:/opt/lingxi/app/
# 运维脚本
scp start.sh stop.sh restart.sh status.sh root@121.40.45.122:/opt/lingxi/app/
```

目录结构：`/opt/lingxi/app/services/<模块>/app.jar`

## 四、启动服务

```bash
cd /opt/lingxi/app
chmod +x start.sh stop.sh restart.sh status.sh
./start.sh
```

`start.sh` 内置环境变量（prod profile、Nacos 地址、DB/Redis/MQ、OSS），逐个 `java -jar` 启动 7 个服务。

## 五、运维脚本

| 脚本 | 作用 |
|------|------|
| `start.sh` | 启动 7 个服务（已运行的跳过） |
| `stop.sh` | 停止 7 个服务 |
| `restart.sh` | 重启（stop → start） |
| `status.sh` | 查看进程 / 端口 / 基础设施容器状态 |

## 六、验证

```bash
./status.sh       # 7 个进程 + 端口
# 网关链路（返回 {"code":400,...} 即通，验证码错误属正常业务响应）
curl -s -X POST http://127.0.0.1:8080/api/v1/auth/login -H "Content-Type: application/json" \
  -d '{"phone":"13800138000","password":"x"}'
# Nacos 服务列表（命名空间 lingxi 下应有 7 个服务）
curl -s "http://127.0.0.1:8848/nacos/v1/ns/service/list?pageNo=1&pageSize=20&namespaceId=lingxi"
```

## 七、代码更新与重新部署

本地改完代码后，按以下步骤更新服务器上的服务：

### 1. 本地重新打包

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-8.jdk/Contents/Home
mvn clean package -DskipTests
```

### 2. 上传新 jar 到服务器（覆盖旧的）

```bash
# 更新全部服务
scp -r services root@121.40.45.122:/opt/lingxi/app/

# 或只上传改动的单个服务（更省时）
scp services/lingxi-hr/app.jar root@121.40.45.122:/opt/lingxi/app/services/lingxi-hr/
```

> 建议先备份旧 jar：`cp services/lingxi-hr/app.jar services/lingxi-hr/app.jar.bak`，方便回滚。

### 3. 重启服务

```bash
cd /opt/lingxi/app

# 全部重启
./restart.sh

# 只重启改动的单个服务（start.sh 幂等，只启动被停掉的那个，其余跳过）
pkill -f lingxi-hr/app.jar
./start.sh
```

> 如果改了 `start.sh` 里的环境变量（IP / 密码 / OSS 配置等），同样用 `./restart.sh` 让新配置生效。

### 4. 验证

```bash
./status.sh                      # 进程 / 端口正常
tail -f logs/lingxi-hr.log       # 看到 Started XXXApplication 即启动成功
curl -s http://127.0.0.1:8080/api/v1/auth/login -X POST -H "Content-Type: application/json" -d '{"phone":"13800138000","password":"x"}'
```

> 回滚：如果新版本有问题，把备份的 `.bak` 恢复回去再重启即可：`cp services/lingxi-hr/app.jar.bak services/lingxi-hr/app.jar && pkill -f lingxi-hr/app.jar && ./start.sh`

## 八、常见问题

| 现象 | 处理 |
|------|------|
| 网关 503 / `No servers available` | Nacos 命名空间 lingxi 没建，或服务没注册；等 1-2 分钟或重启服务 |
| Nacos 控制台打不开 / 反复重启 | 容器内存 512m 不够，重建时 `--memory 768m` |
| 服务启动即退出 | 看 `/opt/lingxi/app/logs/<服务>.log` |
| resume 反复重启 | RocketMQ broker 没就绪，确认 broker 起来了再启 resume |
| 上传文件失败 | 检查 `start.sh` 里 OSS 配置是否正确 |
