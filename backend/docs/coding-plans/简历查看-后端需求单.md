## 1. 背景

HR 人才库页面（`/hr/candidate`）的「查看简历」目前是**占位按钮**（点击 toast），需要后端提供 HR 侧查看候选人简历的接口后，前端才能接入真实数据。

## 2. 现状核对（前端已看代码）

| 现状 | 说明 |
| --- | --- |
| `ResumeFeignClient.getApplication`（`GET /internal/applications/{id}`） | lingxi-hr 内部 Feign，返回投递记录 `InternalApplicationVO`，**含 `resumeId` 但无简历内容** |
| `GET /api/v1/resumes/{id}`（lingxi-resume ResumeController） | **归属校验**（`getOwnedResume`，仅简历本人可看），HR 调用返回 RESUME_NOT_FOUND |
| `/internal/**` | 网关 AuthFilter 白名单放行，**不校验 Token**，不适合前端直连 |

**结论：** 缺少 HR 侧简历内容查看接口；`getApplication` 可作为前置素材（拿 `resumeId`），但需新增两个接口打通。

## 3. 接口方案

### 3.1 lingxi-resume — 内部简历详情接口（✅ 已确认由后端实现）

| 项 | 内容 |
| --- | --- |
| 方法/路径 | `GET /internal/resumes/{id}/detail`（**全量**，免归属校验，仅供 lingxi-hr 内部 Feign 调用） |
| 网关路由 | 已存在：`application.yml` 已路由 `/internal/resumes/**` → lingxi-resume |
| 响应 | `Result<ResumeDetailVO>` |

> **路径说明（2026-08-06）**：`/internal/resumes/{id}/detail` 返回**全量** `ResumeDetailVO`；`/internal/resumes/{id}` 为**精简版**（InternalResumeVO，供 lingxi-job 出题），两者不同，勿混用。
>
> `ResumeDetailVO` 字段：`id / fileName / fileFormat / fileSize / isDefault / parseStatus / resumeMdUrl / facePhotoUrl / cardStructure / candidateName / phone / email / wechat / createdAt / updatedAt`
>
> 实现提示：直接复用 lingxi-resume `ResumeServiceImpl` 的 `toDetailVO`（去掉归属校验即可），`card_structure` 按现有 `parseCardStructure` 解析。

### 3.2 lingxi-hr — HR 侧简历查看接口（前端契约目标，✅ 2026-08-06 已实现）

| 项 | 内容 |
| --- | --- |
| 方法/路径 | `GET /api/v1/hr/candidates/{applicationId}/resume` |
| 鉴权 | `@RequireLogin`，本企业 **ACTIVE 成员**（与现有 list/top5 一致，非成员 4011） |
| 流程 | 校验成员 → 复用 `fetchApplication` 拿 `resumeId`（不存在/跨企业 4300/4301）→ 调 3.1 内部简历接口 → 返回简历详情 |
| 响应 | `Result<ResumeDetailVO>`（D 侧 `ResumeDetailDTO` 透传，全量 15 字段） |
| 错误码 | `4011` 无权限 / `4300` 候选人不存在 / `4301` 无权查看该候选人；简历不存在 → **`4303` 候选人简历不存在** |

> **实现状态（2026-08-06）**：本接口已由 lingxi-hr 实现（`HrCandidateController` + `HrCandidateService`，Feign 调 3.1），编译通过；C 侧 3.1 已落地（`fe150947`，2026-08-05），**本地全链路联调通过**。

## 4. 前端接入口径（接口就绪后）

- `src/services/hr.ts` 新增：
  ```typescript
  export async function getCandidateResume(applicationId: number): Promise<ResumeDetail> {
    return request.get(`/v1/hr/candidates/${applicationId}/resume`);
  }
  ```
- 「查看简历」按钮接真实接口：点击 → `getCandidateResume(record.id)` → 用 `resumeMdUrl` 或 `cardStructure` 渲染简历预览（弹层/跳转）
- `ResumeDetail` 类型可复用候选侧 `src/services/resume.ts` 已有定义（对齐 `ResumeDetailVO`）

## 5. 验收清单

- [ ] HR（本企业 ACTIVE 成员）对某候选人点「查看简历」→ 展示该候选人简历内容
- [ ] 非本企业成员 / 非 ACTIVE 成员 → `4011 无权限操作该成员`
- [ ] applicationId 不存在 → `4300 候选人不存在`
- [ ] 跨企业候选人 → `4301 无权查看该候选人`
- [ ] 候选人未上传简历 / 简历不存在 → `4303 候选人简历不存在`
- [ ] 候选侧 `GET /api/v1/resumes/{id}` 归属校验不受影响（本人仍可看）
